### Hybrid Search ? (feat.RAG 검색 성능)

> 이름 그대로 "섞어서 검색한다"는 뜻인데, 정확히 뭘 섞는 건지 궁금해서 찾아봤다.

- Hybrid = 두 가지 이상을 혼합한 것

- Search = 검색

그래서 뭘 섞는 걸까?

+ **키워드 검색(Sparse/BM25)** : 단어가 정확히 일치하는지로 찾는 전통적인 검색 방식. 제품 코드, 숫자, 고유명사처럼 "의미"보다 "정확한 표현"이 중요한 경우에 강하다.

+ **벡터 검색(Dense/의미 기반)** : [Rag.md](../LLM & Generative AI/Rag.md)에서 정리했던 임베딩 기반 검색. 문장의 "의미"가 비슷하면 단어가 달라도 찾아준다.

근데 왜 굳이 둘 다 필요할까?

벡터 검색만 쓰면 의미는 잘 잡아내는데, "제품번호 A-1234" 같은 걸 물어보면 오히려 엉뚱한 결과를 가져올 때가 있다. (숫자·코드는 의미적으로 비슷한 게 없으니까) 반대로 키워드 검색만 쓰면 동의어나 문맥은 전혀 이해하지 못한다.

<br>

> 그래서 Hybrid Search는 두 검색 결과를 각각 구한 다음, 점수를 합쳐서 최종 순위를 매긴다. 이때 점수를 합치는 대표적인 방법이 **RRF(Reciprocal Rank Fusion)** — 각 검색에서 몇 등을 했는지(순위)를 기준으로 점수를 매겨서 합산하는 방식이다. 점수 스케일이 서로 다른 두 검색 결과를 순위 기준으로 공평하게 합칠 수 있어서 많이 쓰인다고 한다.

결국 하이브리드 서치는 "정확한 매칭"과 "의미 기반 매칭"의 장점을 둘 다 가져가려는 절충안인 셈.

RRF 수식이랑 실제 구현체(BM25+FAISS 조합 등)는 나중에 실습하면서 더 자세히 정리해야겠다.

<br>

## 근데 이거 항상 dense + BM25로 고정인 거야?

> 예전부터 궁금했던 부분이다. 하이브리드 서치라고 하면 다들 당연하다는 듯이 "벡터 검색 + BM25"라고만 말하길래, 이게 정의상 고정된 조합인지 아니면 그냥 관례인지 헷갈렸다.

결론부터 : **"사실상 표준(de facto standard)"**이지, "이론적으로 고정된 정답"은 아니었다.

+ **BM25가 국룰처럼 쓰이는 이유** : 학습(training)이 필요 없고 단어 빈도 통계만으로 계산이 빠르기 때문. Elasticsearch, OpenSearch, Weaviate, Qdrant, Pinecone 같은 대부분의 벡터DB/검색엔진이 하이브리드 기능에 BM25를 키워드 쪽 기본값으로 내장해놨다. 그래서 "하이브리드 서치 붙인다" = "기존 BM25 인덱스 + 벡터 인덱스를 RRF로 합친다"가 실무에서 제일 흔한 조합이 된 거였다.

+ **근데 BM25 말고 다른 선택지도 있음** : **SPLADE**라는 "학습된 희소 벡터(Learned Sparse Retrieval)" 방식이 요즘 BM25 대안으로 뜨고 있다고 한다. BM25는 단순 단어 빈도라 동의어를 전혀 못 잡는데, SPLADE는 신경망으로 관련 단어를 확장해서(예: "자동차" 검색해도 "차량" 관련 문서까지 스코어를 줌) BM25보다 성능이 좋은 경우가 많다고. 다만 임베딩처럼 모델이 필요해서 BM25보다는 무겁다.

+ **Dense 쪽도 꼭 단일 벡터만 쓰는 건 아님** : ColBERT 같은 "multi-vector / late interaction" 방식을 dense 자리에 넣는 경우도 있다고 한다.

> 그러니까 "하이브리드 서치 = BM25 + Dense"라고 외웠던 건 절반만 맞는 말이었던 셈. 정확히는 "희소 검색(Sparse) + 밀집 검색(Dense)을 합친다"가 진짜 정의고, BM25는 그중 가장 무난하고 검증된 기본 선택지였을 뿐이다.
