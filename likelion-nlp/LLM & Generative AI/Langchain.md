### LangChain ? (feat.RAG)

> 랭체인이라는 이름부터 뜯어봤다.

- Lang = Language (언어모델을 다루는 것)

- Chain = 여러 단계를 사슬처럼 엮는다는 뜻

그래서 이게 왜 필요할까?

LLM 혼자서는 프롬프트 하나 던지고 답 하나 받는 게 끝이다. 근데 실제 서비스는 "문서 불러오기 → 쪼개기 → 검색하기 → 프롬프트에 넣기 → 답변 생성하기"처럼 여러 단계가 이어져야 한다. 이 단계들을 매번 코드로 직접 짜고 이어붙이기 번거로우니까, 랭체인이 이 파이프라인을 표준화된 모듈로 미리 만들어둔 것.

> LangChain = LLM을 위한 "레고 블록"

<br>

+ **Model I/O**: 프롬프트 템플릿 관리 + 여러 LLM(ChatOpenAI 등)을 손쉽게 갈아끼울 수 있게 통일된 인터페이스를 제공.

+ **Retriever / VectorStore**: [Rag.md](./Rag.md)에서 정리했던 "검색" 단계를 담당. 벡터 DB에서 질문과 관련된 문서를 찾아오는 역할.

+ **Memory**: 대화 기록을 저장해서 챗봇이 이전 대화 맥락을 기억하게 해줌. 이게 없으면 챗봇이 매번 처음 보는 사람 대하듯 답함.

+ **Chain**: 위 요소들을 순서대로 엮어서 "질문 → 검색 → 답변"까지 한 번에 실행되게 만드는 것.

<br>

>랭체인 시작할 때 주의할 점 하나 : 랭체인은 어디까지나 프레임워크일 뿐, RAG의 원리(로드-청킹-저장-검색-생성)를 모르고 쓰면 결국 문제가 생겼을 때 어디서 막혔는지 디버깅을 못 한다. [Rag.md](./Rag.md)에서 정리한 개념이 먼저고, 랭체인은 그걸 구현하는 도구라고 생각하는 게 맞는 듯.

PDF 로더, Vector DB 연동, Memory 실습 같은 구체적인 코드는 나중에 직접 써보면서 더 채워야겠다.
